Things to try

Experiments that are off unless you ask for them. The ordinary page never loads one, and a switch here is saved only in this browser: nothing is sent anywhere. Each entry says what it needs from the browser and what was measured, including the ones that were dropped.

  • GPU flow field

    In the lab

    The hero's flow field runs on the GPU (WebGPU compute shader) instead of WebAssembly, so it can draw fifty to a hundred times as many particles.

    Needs
    WebGPU
    Measured
    Holds 60 fps from 3,000 to 1,000,000 particles on an Apple GPU (Metal); the WebAssembly field reaches its limit near 150,000. At the site's own density there is no gain, which is why it is off by default.

    Try it once

  • Hero of the day

    Spike

    The hero's flow field is a different picture each UTC day: the noise field moves to a new place and the particles start somewhere new. The same seed draws the same field on the WebAssembly and GPU paths.

    Needs
    WebAssembly
    Measured
    Not yet judged. A seed of 0 is the field the site has always drawn, so with the switch off nothing changes. Add ?seed=anything to any visit to pin one picture, for example /?seed=flow.

    Try it once

  • HDR glow for the GPU field

    Spike

    On a display that can show it, the GPU field draws into a floating-point canvas with extended tone mapping, so where trails pile up they glow brighter than the page's white. Works together with the GPU field; on any other display nothing changes.

    Needs
    an HDR display
    Measured
    Not yet judged: the glow has to be looked at on an HDR screen, and automated tests only check that the browser accepts it and falls back cleanly. Try it with the GPU field and a dense field: /?lab=hero-gpu,hero-hdr&particles=60000.

    Try it once

  • View as agent

    Spike

    A button on every page that shows what a crawler or an AI agent gets there: the page as Markdown (Cloudflare converts it at the edge, with a token estimate), the read-only tools on the MCP server, and the documents agents start from.

    Needs
    Nothing special
    Measured
    Not yet judged. It has to work on the home page, a project and a post, and must never leave Markdown cached under a page's address: the service worker skips any request that asks for Markdown (a unit test) and the fetch bypasses the browser cache.

    Try it once
