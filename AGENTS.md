# AGENTS.md — and3rn3t portfolio

Matt's personal portfolio site. Static-first (vanilla JS `main.js` + `modules/`, `index.html`), served as raw source by GitHub Pages (no bundler), plus a Cloudflare Worker (`worker/index.js`) for dynamic bits (view counts via KV).

## Stack

- Vanilla JS modules (not React); Vite is only the local dev server (`pnpm dev`); **pnpm** (`pnpm@11`, Node `^24.15.0 || >=26` (jsdom 30 / Vitest 5), `.nvmrc` pinned)
- Cloudflare Worker `and3rn3t-portfolio` (`wrangler.toml`; KV bindings `VIEWS_KV` and `GUESTBOOK_KV`): `/views`, `/guestbook` and `/activity`
- Tests: Vitest unit + worker (`tests/unit`, `tests/worker`) and Playwright e2e + axe (`tests/e2e`, served from the raw source like production)
- Shared browser/Worker helpers live in `modules/utils/` (`html.js` escaping, `activity.js`, `data.js`, `icon.js`, `while-visible.js`); the Worker imports them too
- CI workflows (`.github/workflows/`):
  - `quality.yml`: `pnpm validate` + the generated-files check in one job, and e2e + a11y
  - `pages.yml`: deploys the allowlisted source to GitHub Pages, then runs Lighthouse (push only). Add any new root asset to its `sparse-checkout` list or it 404s in production
  - `lighthouse.yml`: weekly and manual Lighthouse runs
  - `update-github-data.yml`: daily refresh of `github-data.json`, the README featured projects and the OG card (it renders only when `.github/og-inputs.sha256` changes), then dispatches `pages.yml`
  - `snake.yml` (README snake on the `output` branch), `codeql.yml`, `gitleaks.yml`, `dependency-review.yml`, `actionlint.yml`, `consistency.yml`, `labeler.yml`, `label-sync.yml`, `release-drafter.yml`, `stale.yml`

## Commands

```bash
pnpm install
pnpm dev             # vite dev server (production ships raw source, there is no build)
pnpm validate        # lint + lint:css + format:check + test:unit + check:refs ← done-gate
pnpm lint:css        # stylelint: spacing/type must use design-system tokens
pnpm check:refs      # every file the site references exists and is in the pages.yml publish allowlist
pnpm test            # unit + e2e
pnpm worker:dev      # wrangler dev worker/index.js (guestbook POSTs need ALLOW_UNVERIFIED_GUESTBOOK=1 in a gitignored .dev.vars; there is no Turnstile secret locally)
pnpm build:worker    # wrangler deploy --dry-run
pnpm deploy:worker   # only when asked
```

## Conventions

- `github-data.json` / `og/default.png` are generated by CI — don't hand-edit
  (regenerate the OG card locally with `pnpm generate:og`; the card is drawn by `scripts/og-card.mjs`). `github-data.json` is slimmed to the
  fields the site reads; if a module needs another field, add it to `REPO_FIELDS`/`USER_FIELDS`
  in `update-github-data.yml`.
- `posts/`, `projects/`, `404.html`, `feed.xml`, the sitemap blog and project blocks and the blocks in `index.html` between
  `<!-- gen:NAME -->` markers (project cards, experience, education, writing) are generated by
  `pnpm generate:site` from `posts-data.json`, `projects-data.json`, `experience-data.json` and
  the starred-repo list in `github-data.json`; CI fails on a diff and the daily data workflow
  re-runs it. Edit the data files or `scripts/templates/`, not the generated HTML. Only stable
  facts are baked in (the cards and project pages show no live numbers),
  because `pages.yml` hashes every `*.html` into the service worker's cache id. The same run writes
  `images/projects/<name>-cover-{light,dark}.svg` for projects without a screenshot. `projects/<slug>/` pages
  are pre-rendered by `scripts/templates/project-page.mjs`; the `@view-transition` opt-in must stay an inline
  `<style>` in each page's `<head>` (`VIEW_TRANSITION_CSS`, see `scripts/templates/chrome.mjs`).
- **CSS** is the design system in `styles/` (Phase 10, `ROADMAP.md`): `core.css` (cascade layers, tokens,
  nav, footer and primitives; every page), `article.css` (project, post and 404 pages) and `home.css` (the
  home page, including its base: the reset, body type and the phone-sized scale). The old `styles.css` is
  gone. Rules for `styles/`:
  - The layer order (`scale, reset, tokens, base, components, sections, utilities`) is declared first in
    `index.html`'s `<head>`, in `scripts/templates/chrome.mjs` **and** at the top of `core.css`; keep them
    identical. Layers are ordered by first appearance, so an `@layer` that comes earlier (e.g. inline
    critical CSS) silently fixes the wrong order.
  - The shared scale (`--space-*`, `--font-size-*`) is in the `scale` layer so a page can adjust it:
    `home.css` makes it a step tighter on phones (a test pins the values), and a page without that
    (project, post, 404) keeps the desktop scale. Don't redefine a scale token in `tokens`; use a new name.
  - Colour comes from semantic tokens (`--surface`, `--text`, `--muted`, `--border`, `--accent`, …) defined once
    with `light-dark()`. Stylelint rejects hex/`rgb()`/named colours in `styles/` outside the token block.
  - `<html data-theme>` is the theme (set before first paint); there is no `body.dark-theme` class.
- Project screenshots are captured by hand: `pnpm capture:screenshots [name]` opens each project's
  `screenshot.url` (in `projects-data.json`) and writes `images/projects/`. Look at the result before
  committing; a demo behind a login (homehub) or showing an empty state needs another URL or none.
- Icons come from an SVG sprite: edit `scripts/build-icons.mjs`, run `pnpm build:icons`, use `icon('name')`.
- `CNAME`, `feed.xml`, `manifest.json` are deploy-sensitive; touch with care.
- `ROADMAP.md` tracks planned work.
- Conventional commits: `type(scope): description`.
- Don't commit or deploy unless explicitly asked.

## Startup and budgets

- `main.js` runs a short critical path (service worker and global handlers, theme, menu, navigation, the UI
  shell), fires `app:ready`, then starts every other feature on its own: near-viewport features with
  `whenNear`, the rest with `whenIdle`. **Do not `await` one optional feature before starting another**, and
  do not import a feature statically from `main.js`. A feature must also work, or degrade, before its module has
  loaded (the contact form is a plain POST; palette and help keys go through `installEarlyShortcuts`).
- `tests/e2e/budgets.spec.js` holds the budgets: by `app:ready`, at most 12 script files and 70 KB; settled, at
  most 28 files, 130 KB and 0.01 CLS. Measure before changing them (the history is in `ROADMAP.md`).
